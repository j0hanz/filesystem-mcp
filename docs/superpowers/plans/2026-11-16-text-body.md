# One Text Body Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One function settles a file's text body (binary, or text with encoding and a lossy mark) for `read`, `stat`, text search and every Rewrite, so they stop drifting.

**Architecture:** `classifyText` in `src/core/read.ts` (internal to `fs.ts`, ADR-015) replaces the two decode paths in `GuardedFileSystem.read` and `readText` and the per-call `decodeUtf16` flag. `TextVerdict`'s `text` arm carries `encoding` and `lossy`; one Rewrite rule in `fs.ts` turns a non-UTF-8, lossy or NUL-holding body into the refusal or skip a Rewrite gives today.

**Tech Stack:** TypeScript on Node (type stripping), `node:test`, zod, `node:buffer` `isUtf8`.

**Spec:** `docs/adr/020-one-text-body-decision.md` (plus the File class entry in `GLOSSARY.md`)

## Global Constraints

- Branch from `main`; one PR for this plan. Never hand-edit versions in `package.json`, `server.json`, `mcpb/manifest.json`, `.codex-plugin/plugin.json`, `.cursor-plugin/plugin.json`.
- Size limit judged on bytes on disk only. UTF-16 past the limit fails `TOO_LARGE` in every read mode (no truncated head).
- `resources/read` keeps serving UTF-16 as a base64 blob (it reads with `binary: 'raw'`, untouched).
- NUL rule unchanged: search skips a NUL-holding body as binary; a Rewrite refuses it; `read` and `stat` treat it as text.
- After code changes run `graphify update .`.
- Gate before PR: `npm run check`.

## Review Focus

1. A UTF-16 file with a lone surrogate or odd trailing byte: decodes with U+FFFD and is marked lossy, never throws. (Task 1 table row.)
2. `edit` on a UTF-16 file still fails with the UTF-16 refusal, not a write of UTF-8 bytes over it. (Task 1 test.)
3. `replace_text` across a folder holding a UTF-16 file skips it, counted as binary as today, and never rewrites it. (Task 1 test.)
4. A file valid in its first lines but Latin-1 further down: `read` with `head: 1` has no `lossy`, a whole read has `lossy: true`. (Task 3 test.)
5. A UTF-8 file containing a literal U+FFFD is not lossy. (Task 1 table row.)

**Interfaces:**

- Produces (in `src/core/read.ts`):
  ```ts
  export type TextEncoding = 'utf-8' | Utf16Encoding;
  export type TextClass =
    | { readonly kind: 'binary' }
    | {
        readonly kind: 'text';
        readonly bytes: Buffer;
        readonly encoding: TextEncoding;
        readonly lossy: boolean;
      };
  /** bytes: the whole body as read. Text bytes are always UTF-8 (UTF-16 re-encoded). */
  export function classifyText(validPath: string, bytes: Buffer): TextClass;
  ```
  Rule: `binaryKind(validPath, bytes.subarray(0, MIME_SAMPLE_SIZE))` — `'binary'` gives binary; `'utf16'` decodes (lossy when a fatal `TextDecoder` throws, then decode non-fatally); otherwise `encoding: 'utf-8'`, `lossy: !isUtf8(bytes)`.
- Produces (in `src/core/fs.ts`):

  ```ts
  export type TextVerdict =
    | {
        readonly kind: 'text';
        readonly bytes: Buffer;
        readonly stats: Stats;
        readonly encoding: TextEncoding;
        readonly lossy: boolean;
      }
    | { readonly kind: 'binary' }
    | { readonly kind: 'tooLarge'; readonly size: number };
  /** The one Rewrite rule: what a Rewrite does with a verdict; undefined means rewrite it. */
  export function rewriteSkipOf(verdict: TextVerdict): SkipVerdict | undefined;
  ```

  `rewriteSkipOf`: `binary` gives `{ kind: 'binary', utf16: false }`; `tooLarge` passes through; text with `encoding !== 'utf-8'` gives `{ kind: 'binary', utf16: true }`; text that is `lossy` or holds a NUL byte gives `{ kind: 'undecodable' }`. `readNamedText` throws `refusalOf(rewriteSkipOf(v), …)`; `rewriteEntry` returns `skipOf(…)` of it. `ReadTextOptions.decodeUtf16` is removed.
