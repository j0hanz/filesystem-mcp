## Findings considered and rejected

- **`debouncedNotificationMethods` for `resources/list_changed`**: the audit
  assumed batch reads externalize several results per call. They do not —
  `putJsonResource` runs once per `list`/`search_text`/`find_files`/`diff`/
  `stat` call, so there is no same-tick burst to coalesce. Nothing to gain.
- **`maxSubscriptions` set to `MAX_WATCHERS`**: streams and watchers are
  different budgets — several `subscriptions/listen` streams legitimately
  share one `fs.watch` (`__tests__/stdio.test.ts` STDIO-004 and STDIO-010 do
  so under `FS_MAX_WATCHERS=1`). A stream cap equal to the watcher cap would
  break them; a separate knob has no demand. The SDK default of 1024 streams
  already bounds it.
- **Replace the tool schema seam (`src/tools/define.ts:417-497`) with a plain
  Zod `inputSchema`**: deletes ~60 lines but re-emits `$schema`, `title`,
  `maximum: 9007199254740991` and `examples` on every tool each session — a
  deliberate token-budget policy. Maintainer's call; not planned.
- **Swap the static-key bearer middleware for `requireBearerAuth`**: measured
  in `docs/plan/2026-09-15-oauth-resource-server/design.md` — loses the RFC
  6750 bare-vs-`invalid_token` challenge split and changes the 401 body; no
  IdP exists to justify it. Revisit with issued tokens.
- **`scopeChallenge` / `requireScopes`, `maxRequestBodySize`**: documented,
  not in the installed 2.0.0 (SDK main only). Needs an SDK upgrade first.
- **The `subscriptions/listen` watcher gate (~280 lines across
  `src/transport/stdio.ts`, `http.ts`, `shared.ts`)**: no SDK hook exists in
  2.0.0 or on SDK main. Upstream ask filed as
  https://github.com/modelcontextprotocol/typescript-sdk/issues/2827; the
  deletion map for when it ships is
  `docs/plan/2026-09-15-sdk-listen-hook/deletion-map.md`.
- **`icons`, `droppedInputResponseKeys`**: cosmetic / malformed-peer-only;
  not worth a plan.
