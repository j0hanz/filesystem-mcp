## Findings considered and rejected

### 2026-11-14, deep audit at `366c4c96`

Scope: the whole repository in nine categories, eight read-only agents. The
advisor re-read the cited code for every planned finding. Nothing was
reproduced by running the server; no test, build or benchmark was run, so
every cost figure in plans 121 and 122 is derived from reading.

- Adding more names to the built-in secret-file list (`*.tfvars`,
  `.bash_history`, `*.kdbx`, `rclone.conf` and others,
  `src/core/sensitive.ts:283-328`): a policy choice that blocks files users
  read today; `--deny` already covers it per installation.
- A fixed placeholder API key in a Docker example
  (`docs/configuration.md:390`): the same page shows `openssl rand`
  elsewhere; not worth a startup check for known strings.
- Dev-only `npm audit` advisories (3 high, all through
  `@anthropic-ai/mcpb`): the packer's affected code path is not used by
  `pack`. `npm audit --omit=dev`: 0 vulnerabilities.
- Splitting `src/core/fs.ts` (2,245 lines): ADR-008, 011, 012 and 015 put
  ownership in that class on purpose; no import cycles; navigation cost only.
- A pre-commit hook and a watch script: `node --test --watch` already works
  and CI runs every step separately.
- One agent-guide file instead of identical `AGENTS.md` and `CLAUDE.md`: no
  drift today.
- Line-mode regex over blocks of lines (`src/core/matcher.ts:723-741`),
  a new MCP server per HTTP request (`src/transport/http.ts:311-320`),
  page snapshots capped by count (`src/core/store.ts:288-300`), a
  synchronous stat when attaching a watcher
  (`src/core/watcher-registry.ts:178`): all unmeasured; revisit with a
  profile.
- Removing the repeated path validation per scanned file
  (`src/core/search.ts:110`, `src/core/path.ts:486-503`): the largest
  performance cost found, but it is the sandbox check. It needs a security
  design, not an executor plan.
- Checked and found sound: API-key comparison (hashed, timing-safe),
  middleware order on `/mcp`, non-loopback bind rules, `requestState`
  sealing and binding, the sensitive-file check on the real path, workflow
  action pinning and input handling, the Docker user, paging (no re-walk),
  rate-limiter and lock-map bounds, the undo journal's caps, RE2 compile
  and free, the SDK package set (current and aligned), Node version
  consistency, lockfile.
- The two registry token files in the repository root are git-ignored and
  were never committed (`git log --all` shows nothing). They were not opened.
- Not audited in this run: the example clients other than `browser`, the
  demo scripts, `scorecard.yml` in full, whether README install snippets
  run, external client support for roots or Skills.
