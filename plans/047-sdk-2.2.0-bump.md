## Why this matters

`@modelcontextprotocol/server`, `/node`, `/express` and (dev) `/client` are
**exact-pinned** on purpose — the maintainer audits each SDK release against
this codebase rather than letting semver ranges float. `server@2.2.0` and
`client@2.2.0` were published; `node` (2.1.0) and `express` (2.0.1) have no
newer release and their peer ranges (`@modelcontextprotocol/server ^2.1.0`)
already accept a 2.2 server. Staying behind accumulates migration distance and
forgoes three fixes that touch code paths this server uses (below). The prior
SDK audits also left a standing instruction: "re-check on the next SDK bump"
whether three doc-only symbols became real exports. This plan does the bump,
the re-check, and records the outcome.

- `server@2.2.0` changelog (`packages/server/CHANGELOG.md` in
  `modelcontextprotocol/typescript-sdk`) — **patch changes only**:
  1. Sending a notification on a closed connection no longer produces a
     briefly unhandled promise rejection in addition to the returned
     rejection. (This server sends `resources/updated` and `list_changed`
     notifications from `src/resources.ts` / `src/core/store.ts` callbacks.)
  2. Fix a stack overflow in `createMcpHandler` when the factory returns the
     same server instance for more than one request. (This server returns a
     fresh instance per request — `src/transport/http.ts:311-340` — so this is
     not exercised, but it is the handler we use.)
  3. `createMcpHandler` now ends a `subscriptions/listen` stream right after
     the acknowledgement when it honored **none** of the requested notification
     types, instead of holding the stream open. (This server's listen handling
     lives in `src/transport/shared.ts` `listenSubscriptionUris` and the HTTP
     watcher gate in `src/transport/http.ts:190-250`; the tests are
     `__tests__/subscriptions-listen.test.ts` and `__tests__/http-transport.test.ts`.)
     Plus `core@2.2.0` (its own changelog is at
     `node_modules/@modelcontextprotocol/core/CHANGELOG.md` after install).

- Symbols this codebase depends on that the installed 2.1.0 `d.mts` exports
  (re-verify after the bump): `DEFAULT_MAX_REQUEST_BODY_SIZE`
  (`server/dist/index.d.mts:756`, imported by `src/transport/http.ts`);
  `Server.listRoots()` and `Server.getClientCapabilities()`
  (`server/dist/createMcpHandler-*.d.mts:3067, 3195`) — **ADR-002's removal

- Standing re-check from `plans/README.md` ("Findings considered and

  `createListenRouter` (would replace `listenSubscriptionUris` in

- `@typescript-eslint/no-deprecated` is `error` in `eslint.config.mjs`, so any
  newly deprecated SDK API this code calls fails `npm run lint`. The two
  deliberate legacy calls carry `eslint-disable-next-line` with a
  `sunset(SEP-2577)` marker (`src/transport/stdio.ts`, `src/tools/define.ts`).

- Known flake to distinguish from a regression: a bare `test failed` about

## STOP conditions

Stop and report back (do not improvise) if:

- `npm view @modelcontextprotocol/server version` ≠ `2.2.0` (a newer release
  exists; the changelog analysis above is incomplete).
- `npm ls` shows two `core` versions, or `invalid` next to `node` / `express`
  — the peer ranges changed; report the tree.
- `npm run build` or `npm run lint` fails on an SDK type or a newly
  `@deprecated` API — the fix would be a `src/**` change, which is out of
  scope; report the file:line and the diagnostic.
- `listRoots(` or `getClientCapabilities(` is no longer declared — this is
  **ADR-002's removal trigger**; the legacy-path removal is its own project
  (see `docs/adr/002-legacy-protocol-paths-sunset.md`) and must not be
  attempted here.
- `subscriptions-listen.test.ts` or `http-transport.test.ts` fails with an
  assertion message (not the bare `test failed` flake) — changelog item 3
  changed observable behavior for this server's listen handling.
- Any test's pass/skip count changes.
