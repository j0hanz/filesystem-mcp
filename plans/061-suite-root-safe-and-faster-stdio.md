## Why this matters

Two small changes, both about the signal the suite gives:

1. **Red as root.** `TC-FUNC-009l` makes a file write-only (`0o222`) and
   expects the metadata read to fail. Root ignores mode bits, so as root the
   read succeeds and the test fails. GitHub runners are not root, so CI never
   sees this, but cloud agent sandboxes often run as uid 0. PR #62's body
   (written by an agent session) reads "Full suite: 572 passing (one
   pre-existing root-only env failure unrelated to these changes)". An agent
   that learns to wave away one red test will wave away the next one too.
2. **`stdio.test.ts` sets the suite's wall time.** Measured on Windows: the
   whole suite takes about 20 s, and 13.2 s without `stdio.test.ts`. On its
   own, the file takes 16–26 s. Its `Stdio subscription lease lifecycle`
   describe (14 tests: 10 literal `it(` calls plus 4 generated by the STDIO-015/016
   loop at the end) spawns a fresh server subprocess per test and runs
   them one after another. Each test owns its root and subprocess, so they can
   run concurrently. Expected gain: about 5–6 s per local run. That is modest,
   and the main value is a faster agent edit-test loop.

```ts
it('TC-FUNC-009l: an append whose metadata reads fail still reports success', async (t) => {
  // A POSIX write-only (0222) file appends fine but cannot be opened 'r',
  // so the sample/line-count reads throw: the append is the commit point

  if (process.platform === 'win32') return t.skip('POSIX-only 0222 append target');

```

It is the only chmod-to-deny test in `__tests__/`. The other `chmod`,
`core-fs.test.ts:316` (`0o600`), denies nothing. Nothing in `__tests__/`
checks `getuid` today.

- `__tests__/stdio.test.ts` has three top-level describes:
  - `:54` `Stdio Transport (real subprocess)`: **one shared** subprocess from
    `before()` (`:59-62`). Its tests share it, so **do not** make it
    concurrent.
  - `:186` `Stdio CLI flags (real subprocess)`: a shared `tmpDir` from
    `before()`, with one subprocess per test (3 tests, small gain). Leave it.
  - `:250` `Stdio subscription lease lifecycle`: **no** `before`/`after`.
    Each test does `const tmpDir = await createTestRoot();` (or `root`),
    spawns its own harness, and cleans up in its own `finally`. Example,
    `STDIO-006` at `:315-337`:

```ts
it('STDIO-006: closing a listen frees a one-slot watcher budget', async () => {
  const tmpDir = await createTestRoot();
  const harness = await createStdioClient(tmpDir, {
    FS_MAX_WATCHERS: '1',
  });
  try {
    ...
  } finally {
    await harness.close();
    await cleanupTestRoot(tmpDir);
  }
});
```

- `node:test`: `describe(name, { concurrency: true }, fn)` runs that
  describe's tests concurrently. No describe in the repo sets this today.
